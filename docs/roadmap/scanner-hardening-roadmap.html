Scanner Hardening Roadmap

The tiered-confidence framing is the product's best asset — but the marquee authz/auth oracles are false-positive machines and the tool has no defenses of its own. This is what to change, in order.

The three findings that drive the plan

Where the gap actually is

The engineering discipline is above the norm for a project this size. The gap is that the parts a buyer judges first haven't caught up to the bar the rest of the code sets.

FINDING 01

Oracles don't prove what they claim

BOLA compares two authorized identities on a fixed id=1; broken-auth never checks that auth was required. Both fire on healthy endpoints.

→ false positives + false negatives
FINDING 02

The tool has no security of its own

No API authentication and an unvalidated target URL make a hosted deploy an SSRF-as-a-service pivot. The authorized:true flag is a checkbox, not access control.

→ blocks any "production-ready" claim
FINDING 03

Sequential engine runs shallow

Sync httpx, checks one at a time, one flat 500-request cap spread across ops × checks × payloads. A 100-op spec gets ~5 requests per endpoint, total.

→ slow scans, thin coverage

Change set A · detection accuracy

Rebuild the flagship oracles

Model each on the one check that is already sound — write_oracle.py, which proves a mutation persisted across identities with a read-back. Move authz/auth from "responses look alike" to an explicit authorization baseline.

BOLA app/engine/checks/authz.py:26 OWASP API1

current replay, byte-compare

# fixed id, two authorized identities
ra = send(GET, path{id=1}, creds[0])
rb = send(GET, path{id=1}, creds[1])
flag if ra.ok and rb.ok
        and ra.text == rb.text

Identical bytes across two authorized callers is the expected result for any shared or public object. Never reads a foreign object, so real BOLA is untested.

rebuilt ownership-differential

# A owns X; can attacker B read A's X?
own = send(X, high_priv)   # owner view
vic = send(X, low_priv)    # attacker
anon = send(X, no_auth)    # baseline
flag CONFIRMED if vic ≈ own
   and anon in (401,403)   # does gate

Proves B sees A's private object and the endpoint does authenticate — so a match is a real cross-tenant read, not a public resource. Add sequential/UUID id enumeration + similarity scoring over byte-equality.

Broken Authentication app/engine/checks/auth.py:24 OWASP API2

current garbage header

forged = {Authorization:
  "aidetector-forged-<hex>"}  # not Bearer
r = send(method, path, forged)
flag if r.status < 400

A genuinely public endpoint returns 200 to any header → false positive. The token isn't even well-formed, so no real bypass class is exercised.

rebuilt baseline-gated + JWT suite

anon = send(op, no_auth)
if anon.status not in (401,403): skip
for t in [alg_none, weak_secret,
     kid_inject, foreign_user, expired]:
  if send(op, t) ≈ valid: flag CONFIRMED

First confirm auth is required, then run a real forgery suite (alg=none, weak secret, kid/jku injection, algorithm confusion, cross-user replay). Names the bypass class in the finding.

BFLA app/engine/checks/authz.py:56 OWASP API5

current substring match

priv = "/admin" in path       # literal
r = send(op, lowest_priv)
flag if r.status < 400

Misses scope/role-encoded privilege and versioned admin paths; flags on bare status without a high-priv baseline to compare against.

rebuilt scope-aware differential

priv = admin_path or scope_in(op)
hi = send(op, high_priv)     # reference
lo = send(op, low_priv)
flag if hi.ok and lo ≈ hi  # same fn

Derive "privileged" from the security scope the parser already keeps, and confirm the low-priv identity gets the same privileged function the high-priv one does.

Sequenced delivery

Roadmap

Ordered by what unblocks a trustworthy result first. P0 is correctness and self-defense; P1 is depth and reliability; P2 is coverage and polish.

P0 Trust
before any "production" claim
1

Rebuild BOLA + broken-auth oracles

Ownership-differential + explicit authorization baseline, modeled on write_oracle.

2

API authentication + SSRF egress guard

Close the open front door and the open target field together.

3

Redact secrets/PII from stored evidence

Sanitize response_sample, run snapshots, and the PDF report.

4

Constrain the adjudicator

Untrusted-evidence framing, minimal tools, drop bypassPermissions.

P1 Depth
real scans on real specs
5

Async engine + per-host rate limiting

Replace the flat 500-cap with adaptive / per-op budgets; concurrency with a token bucket.

6

Auth-token refresh + 429 backoff

A mid-scan token expiry currently turns every later check into a silent false negative.

7

Fix the OOB transport

One-shot interactsh-client subprocesses can't correlate — use a persistent sidecar.

8

Schemathesis input gen + broaden adjudication

Property-based/negative inputs; adjudicate the FP-prone injection leads, where triage helps most.

P2 Coverage
breadth & integration
9

Stateful sequences + robust $ref

RESTler-style create-as-A → read-as-B; resolve nested allOf/oneOf/arrays/remote refs.

10

SARIF/CVSS output + live-target tests

Make findings CI-consumable; cache adjudication verdicts to stop re-spending tokens on re-runs.

Libraries to adopt, by gap

Highest leverage first. Each replaces hand-rolled code that currently under-covers, or adds a capability the engine lacks entirely.
